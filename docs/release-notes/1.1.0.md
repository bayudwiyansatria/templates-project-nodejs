# Release Notes

## Version 1.1.0

### 📅 Release Date

2026-08-05

### 📖 Overview

1.0.0 shipped a scaffold: build, test, lint, and documentation configuration, with `src/` holding a single `index.ts`
and two demo functions. What it did not ship was an answer to the first question anyone forking it asks — where does
code go.

This release answers that, and repairs the tooling that was supposed to keep the answer honest. Auditing downstream use
of 1.0.0 showed its defects being copied forward untouched — not adapted, not noticed, just inherited along with
everything else:

| Defect                            | Effect                                                                 |
| --------------------------------- | ---------------------------------------------------------------------- |
| `lint:run` with no path argument  | ESLint ran and reported success while checking nothing                 |
| `npm run lint & npm run test:run` | `&` backgrounds the linter, so failures never reached the exit code    |
| `dev` invoking a runtime CLI      | a script that cannot run; the CLI was never a dependency               |
| `peerDependencies: { rollup }`    | every downstream project asked to install a build tool it does not use |
| `main` pointing at a `.js` bundle | under `"type": "module"`, the CommonJS entry was unloadable            |

A defect in a template is not one bug. It is one bug per library — and not one of the five fails a build, which is why
every one of them survived into 1.1.0.

### ⚠️ Breaking Changes

- **Bundle extensions**: `lib/index.min.js` → `lib/index.min.cjs`, and `lib/index.min.umd.js` → `lib/index.min.umd.cjs`.
  See [Fixes](#-fixes) — the CommonJS entry was unloadable before this. Anything referencing the old paths directly must
  be updated
- **Module resolution**: `baseUrl: "src"` replaced by `paths: { "@/*": ["./src/*"] }`, so imports move from `'types'` to
  `'@/types'`
- **Peer dependency removed**: `peerDependencies: { rollup }` is gone. A library built with Rollup does not require its
  consumers to install Rollup
- **Lint configuration**: `.eslintrc.json` and `.eslintignore` replaced by `eslint.config.ts`. ESLint 10 cannot read the
  former

### 🚀 Features

- **Layered working structure**: `core/` (domain), `types/`, `constants/`, `exceptions/`, `utils/` — each with an
  `index.ts` barrel carrying an `@module` block stating what belongs in the layer and what may import it
- **Enforced layer boundary**: `types/`, `constants/`, `exceptions/`, and `utils/` may not import from `@/core`, via
  `no-restricted-imports` in `eslint.config.ts`. A convention survives only as long as everyone remembers it, and the
  import that breaks this one looks exactly like every other import at the point it is written
- **`LibraryException`**: a base exception carrying a stable `code` to branch on and an optional `cause` to keep a
  wrapped failure attached. `cause` is declared on the class rather than accepted through `ErrorOptions`, which is
  ES2022 — the ES2020 baseline is unchanged
- **Collision-free imports**: the `@/*` mapping, agreed by TypeScript (`paths`), Jest (`moduleNameMapper`), and Rollup
  (`@rollup/plugin-typescript`). The previous `baseUrl` form produced bare specifiers, and `types`, `constants`, and
  `utils` are all real packages on npm
- **`exports` map** in `package.json`, so modern Node and bundlers resolve the package instead of falling back to legacy
  `main`/`module`
- **Documentation site**: `docker/docs.Dockerfile` and nginx serving a landing page, the TypeDoc reference at `/docs/`,
  the coverage report at `/coverage/`, and the HonKit book at `/book/`, published on port 80 at `http://localhost/`
- **Documentation gates**: `typedoc.json` gains `treatWarningsAsErrors` with `validation.notDocumented`, `invalidLink`,
  `notExported`, and `rewrittenLink`; `skipErrorChecking` is now `false`. An undocumented export or an unresolvable
  `{@link}` stops the build instead of scrolling past as a warning
- **Restructured book**: `getting-started/`, `guides/`, and `reference/`, with an index stating which docs are living
  and which are point-in-time records
- **Tests for the new modules**, at 100% statement, branch, and line coverage. `test/index.spec.ts` is unchanged and
  still passes, which is what proves the public surface survived the restructure

### 🔧 Enhancements

- **HonKit replaces GitBook**: `gitbook-cli` is abandoned and no longer installs, and the image building it was pinned
  to `node:10-buster`
- **`docs/book.json` `root`** corrected from `./docs` to `.` — the file already lives inside `docs/`
- **Coverage reporting**: `lcovonly` + `html`, so Codecov still receives `lcov.info` while the site serves a browsable
  report; `collectCoverageFrom` scoped to `src/**`
- **`tsconfig.test.json`**: its `types` array sat outside `compilerOptions`, where TypeScript ignored it
- **UMD global** renamed `BayuAuthClient` → `TemplatesProjectNodejs`, a leftover from an unrelated project
- **Rollup** emits `exports: 'named'` for CommonJS and UMD, so a fork adding a default export finds out at the moment it
  writes the code rather than at the next build, and drops warnings originating in `node_modules`
- **Release workflow** threads the `lib` artifact through build → test → publish, and invokes `npm run release`
- **Docker Compose isolation**: an explicit project name, since Compose otherwise derives one from the containing
  `docker/` directory — a name every project using this layout would share, so only one could run at a time
- **Dated change logs** use ISO form — `2026-apr-19.md` → `2026-04-19.md` — and the 1.0.0 release date is corrected to
  2026-04-19, matching `CHANGELOG.md`

### 🩹 Fixes

- **The CommonJS entry was unloadable.** `package.json` declared `"type": "module"` while `main` pointed at
  `lib/index.min.js`; under `type: module` Node reads every `.js` file in the package as ESM, so the CommonJS bundle
  parsed as ESM and `require()` of the package returned nothing usable.

  Nothing caught it — the build succeeded, the suite passed, and TypeScript was satisfied, because none of the three
  ever loads the packaged form. It surfaced from `node -e "require('./lib/index.min.js')"` while verifying the new
  `exports` map, and that check is now a step in the [Publishing Guide](../guides/publishing.md).

- **`lint:run` linted nothing**: `eslint -c .eslintrc.json --ext=.ts,tsx` was missing a path argument. Now `eslint src`
- **`npm test` hid lint failures**: `npm run lint & npm run test:run` backgrounds the linter on POSIX shells, so a lint
  failure never reached the exit code. Now `&&`
- **`dev` invoked a runtime CLI** that was never a dependency and has no meaning in a library. Now Rollup watch mode

### 🗑️ Removals

- The root `Dockerfile` and `docker-compose.yaml`, whose final image ran `tail -f /dev/null` — it built `lib/` and
  `dist/` and served neither
- `docker/book.Dockerfile` and `docker/docker-compose.book.yaml`, the `node:10` GitBook build
- devDependencies `@eslint/config-array`, `eslint-plugin-import`, and `eslint-config-typescript`, none of which any
  configuration referenced
- The Deployment section of `AGENTS.md`, describing an Azure Static Web Apps workflow, a `staticwebapp.config.json`, and
  a `DEPLOYMENT.md` — none of which exists in this repository, and git history shows none ever did

### 🔐 Security

- An `overrides` block pins vulnerable transitive dependencies (`glob`, `brace-expansion`, `undici`, `test-exclude`)
- Removing `peerDependencies: { rollup }` and three unused devDependencies reduces what a consuming project is asked to
  install
- Security reporting policy remains in [SECURITY.md](../../SECURITY.md)

### ⬆️ Upgrading From 1.0.0

A fork upgrades by merging. The changes needing attention:

| Was                               | Now                             |
| --------------------------------- | ------------------------------- |
| `import … from 'types'`           | `import … from '@/types'`       |
| `lib/index.min.js`                | `lib/index.min.cjs`             |
| `lib/index.min.umd.js`            | `lib/index.min.umd.cjs`         |
| `.eslintrc.json`, `.eslintignore` | `eslint.config.ts`              |
| `baseUrl: "src"`                  | `paths: { "@/*": ["./src/*"] }` |
| `peerDependencies: { rollup }`    | removed                         |

Consumers using `require()` were already broken and need no change beyond upgrading. The lockfile must be regenerated:
the 1.0.0 lock resolves `eslint-config-typescript` → `@typescript-eslint@5`, which cannot coexist with ESLint 10.

### 🐛 Known Issues

- `npm audit` reports two high-severity advisories in `immutable <= 4.3.8`, reached only through `honkit`, with no
  upstream fix available ([GHSA-v56q-mh7h-f735](https://github.com/advisories/GHSA-v56q-mh7h-f735),
  [GHSA-xvcm-6775-5m9r](https://github.com/advisories/GHSA-xvcm-6775-5m9r)). Both are denial-of-service classes in a
  documentation-build devDependency that never enters the published tarball — `files` is `lib/` only. Clearing it needs
  HonKit to move off the affected `immutable` range.
