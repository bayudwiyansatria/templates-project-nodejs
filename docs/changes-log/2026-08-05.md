# Changelog - Working Structure, Toolchain Modernization & Documentation System (2026-08-05)

## Overview

A drift-reconciliation pass against two sibling repositories:
[`cloudflare-boilerplate`](https://github.com/bayudwiyansatria/cloudflare-boilerplate), which is three releases ahead on
structure and tooling, and [`nodejs-auth-client`](https://github.com/bayudwiyansatria/nodejs-auth-client), which is a
published library grown from this template.

The question asked was narrow: what has the boilerplate solved that this template has not, and what does the fork show
about which of those answers a _library_ actually needs. The fork turned out to be the more useful of the two, for two
reasons. It had independently converged on a layout close to the boilerplate's, which corroborated the shape. And it had
inherited every defect in this template verbatim — including `@cloudflare/workers-types` in a browser-only auth library
— which settled the priority of fixing them.

Deliberately left behind from the boilerplate: `scripts/check-jsdoc.mjs`, and its `CONTRIBUTING.md` / `SECURITY.md` /
`SUPPORT.md` / `CODE_OF_CONDUCT.md`, which still carry GitHub's placeholder prose where this repository's are filled in.
`.npmignore` was left behind too — `package.json#files` already governs the tarball and takes precedence over it.

## Added

### A layered `src/`

- `src/core/` (domain), `src/types/`, `src/constants/`, `src/exceptions/`, `src/utils/`, each with an `index.ts` barrel
  carrying an `@module` block that states what belongs in the layer and what may import it. Generalized from the layout
  the fork converged on (`types/ constants/ utils/ env/ client/`), with `core/` kept as the placeholder name and
  documented as the thing to rename.

  `src/index.ts` is now a barrel with no implementation. Making it one means the published surface is something you can
  see rather than something you have to read the codebase to determine — which is also what lets TypeDoc document
  exactly the set a consumer can reach.

### `LibraryException`

- `src/exceptions/LibraryException.ts` — the one addition neither reference repository has. The boilerplate keeps its
  error types inside `core/`; the fork sets bare error strings on its state object, so a consumer of
  `@bayudwiyansatria/auth-client` has nothing to narrow on but message text.

  Carries a stable `code` to branch on and an optional `cause` to keep a wrapped failure attached. `cause` is declared
  on the class rather than accepted through `ErrorOptions`, because the two-argument `Error` constructor is ES2022 and
  this project's `lib` is ES2020 — declaring the field keeps chaining available without moving the language baseline for
  every consumer. `Object.setPrototypeOf` is there because without it `instanceof` returns `false` for subclasses in the
  downlevelled CommonJS bundle, which would defeat the entire point of having a base class.

### A lint-enforced layer boundary

- `eslint.config.ts` restricts `types/`, `constants/`, `exceptions/`, and `utils/` from importing `@/core`. The rule
  codifies observed practice rather than imposing a new constraint: the fork's `utils/*` already import only from
  `types`, so the arrow it describes is one real code already follows.

  It is a lint rule rather than a note in a comment for the reason the boilerplate gives for its kernel boundary — the
  value of a boundary is that it holds under later edits, and the import that breaks it is indistinguishable from every
  other import at the point it is written.

### Documentation site

- `docker/docs.Dockerfile`, `docker/docker-compose.docs.yaml`, `docker/nginx/{index.html,default.conf}` — nginx serving
  a landing page plus `/docs/` (TypeDoc), `/coverage/` (Jest HTML), and `/book/` (HonKit). Published on `80:80` rather
  than the boilerplate's `8080:80`, so the URL carries no port.

  One improvement over the source: the boilerplate's image runs `npm run lint:run` only, with a comment explaining that
  it has no spec files and Jest exits non-zero on an empty suite. This repository has real specs, so the image runs the
  full `npm run test` and the coverage report it serves is produced by that same step.

### Documentation gates

- `typedoc.json` gains `treatWarningsAsErrors` with `validation.notDocumented`, `invalidLink`, `notExported`, and
  `rewrittenLink`; `skipErrorChecking` becomes `false`. On its first run it failed the build on a `README.md` link to
  `docs/changes-log/2026-apr-19.md`, a file renamed earlier in this same session — which is precisely the class of rot
  it exists to catch.

  `entryPoints` stays `./src/index.ts` rather than adopting the boilerplate's `expand` over `./src`. For a library the
  API reference should mirror what consumers can import; internals are not documented for people who cannot reach them.

### Tests

- `test/core/Metadata.spec.ts` and `test/utils/Text.spec.ts`. `test/index.spec.ts` is **unchanged** and still passes,
  which is the evidence that the public surface survived the restructure. Coverage is 100% of statements, branches, and
  lines.

## Changed

### Module resolution

- `baseUrl: "src"` → `paths: { "@/*": ["./src/*"] }`, with `moduleDirectories` in Jest replaced by a matching
  `moduleNameMapper`.

  Both reference repositories use `baseUrl`, which is why the fork writes `import type { … } from 'types'` and
  `import { … } from 'constants/storage'`. Those are bare specifiers, and `types`, `constants`, and `utils` are all real
  published packages — the meaning of such an import depends on what happens to be installed. `paths` needs no `baseUrl`
  as of TypeScript 4.4, and the `@/` prefix cannot collide.

  Verified end to end: `tsc --noEmit` resolves, Jest resolves, and no bare `@/` specifier survives into any bundle.

### Toolchain

- ESLint 8.23.1 → 10 with `.eslintrc.json` + `.eslintignore` replaced by `eslint.config.ts`; `@typescript-eslint` 5 → 8;
  TypeScript 4.7.4 → 5.0.4; Jest 29 → 30; TypeDoc 0.23 → 0.28. Plus the boilerplate's `overrides` block pinning
  vulnerable transitives.

  Two rule renames were forced by `@typescript-eslint` v8: `@typescript-eslint/semi` was removed outright (already
  disabled, so simply gone) and `no-empty-interface` became `no-empty-object-type`, kept disabled as before.

  One rule is kept **stricter** than both siblings: `@typescript-eslint/no-unused-vars` stays an error with an `^_`
  escape, where the boilerplate switches it off. An unused import in a library is dead weight that ships.

  The install needed the lockfile regenerated. The old lock still resolved `eslint-config-typescript` →
  `@typescript-eslint@5`, which cannot coexist with ESLint 10.

### Documentation

- HonKit replaces GitBook. `gitbook-cli` is abandoned and no longer installs on any current Node; the image building it
  was pinned to `node:10-buster`. `docs/book.json` also had `root: "./docs"` while already sitting inside `docs/` — the
  fork got this right and the template did not.
- `docs/` restructured to `getting-started/` + `guides/` + `reference/`, taken from the fork rather than the
  boilerplate's `architecture/` + `guide/`. A library's documentation needs an Installation and a Quick Start, and the
  fork's `reference/directory-structure.md` is the page a fork actually reaches for.
- `docs/README.md` becomes an index with per-directory tables and an explicit statement of which docs are living and
  which are point-in-time records — the boilerplate's convention.
- `docs/changes-log/2026-apr-19.md` → `2026-04-19.md`, and `docs/release-notes/1.0.0.md`'s release date corrected from
  "May 8, 2026" to 2026-04-19, which is what `CHANGELOG.md` and the changes-log entry both say.

### Coverage

- `coverageReporters` becomes `lcovonly` + `html` so the site can serve a browsable report at `/coverage/` while Codecov
  still receives `lcov.info`; `collectCoverageFrom` is scoped to `src/**`.

### `tsconfig.test.json`

- Its `types` array sat outside `compilerOptions`, where TypeScript ignores it. Moved in, with `@types/jest` added
  alongside `@types/node` — without which moving it would have removed the Jest globals from the spec compilation.

## Fixed

### The packaging bug

- `package.json` declared `"type": "module"` while `main` pointed at `lib/index.min.js`. Under `type: module` Node reads
  every `.js` file in the package as ESM, so the CommonJS bundle parsed as ESM and `require()` of the package returned
  nothing usable.

  Nothing caught it. The build succeeded, the suite passed, and TypeScript was satisfied, because none of the three ever
  loads the packaged form. It surfaced from `node -e "require('./lib/index.min.js')"` while verifying the new `exports`
  map, and that check is now a step in the publishing guide.

  CommonJS now emits to `lib/index.min.cjs` and UMD to `lib/index.min.umd.cjs`. Both extensions are unambiguous whatever
  `type` says. The fork has the identical defect.

### Scripts

- `lint:run` was `eslint -c .eslintrc.json --ext=.ts,tsx` with no path argument, so ESLint checked nothing. Now
  `eslint src`.
- `npm test` was `npm run lint & npm run test:run`; `&` backgrounds the linter on POSIX shells, so a lint failure never
  reached the exit code. Now `&&`.
- `dev` invoked `miniflare --live-reload --debug --modules lib/index.min.mjs` — a Cloudflare leftover, with Miniflare
  not among the dependencies. Now `rollup -c rollup.config.ts --watch`.

### Packaging

- Added an `exports` map so modern Node and bundlers resolve the package rather than falling back to `main`/`module`.
- Removed `peerDependencies: { rollup }`. A library built with Rollup does not require its consumers to install Rollup.
- UMD global renamed `BayuAuthClient` → `TemplatesProjectNodejs`. It had been carrying the name of an unrelated project
  since the initial commit.

## Removed

- The root `Dockerfile` and `docker-compose.yaml`. The image built `lib/` and `dist/`, then ran `tail -f /dev/null` — it
  served none of what it built, and a library has nothing to containerize.
- `docker/book.Dockerfile` and `docker/docker-compose.book.yaml`, the `node:10` GitBook build.
- devDependencies `@eslint/config-array`, `eslint-plugin-import`, and `eslint-config-typescript`. No configuration
  referenced any of them, and all three had propagated into the fork.
- The Deployment section of `AGENTS.md`, which described an Azure Static Web Apps workflow, a
  `staticwebapp.config.json`, and a `DEPLOYMENT.md`. None of the three exists in this repository, and git history shows
  none ever did.

## Notes

`npm audit` reports two high-severity advisories in `immutable <= 4.3.8`, reached only through `honkit`, with no
upstream fix available. Both are denial-of-service classes in a documentation-build devDependency that never enters the
published tarball. `cloudflare-boilerplate` carries the same exposure for the same reason.
